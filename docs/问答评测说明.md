# 问答评测说明

> 本文只说明“问答评测”这一件事：先生成检索和回答，再做评分与汇总。
> 不展开实验结果，不记录周报内容。

## 1. 评测目标

检查两件事：

- **检索是否命中**：能不能把相关记忆找出来
- **回答是否正确**：LLM 回答和标准答案是否一致

## 2. 相关模块

| 模块 | 作用 |
|---|---|
| `dev-tools/python/generate_qa_answers.py` | 先做检索，再生成回答 |
| `dev-tools/python/evaluate_qa_results.py` | 读取结果文件，做评测 |
| `benchmark-results/qa-answers/` | 第一阶段输出结果目录 |
| `benchmark-results/qa-evaluation/` | 第二阶段评测结果目录 |

## 3. 基本流程

1. 准备好写入完成的记忆库
2. 运行问答生成脚本
3. 运行评测脚本
4. 查看汇总和明细

## 4. 常用命令

### 生成问答结果

```bash
cd /home/zzx/py/Memind-Local-Dev

python3 dev-tools/python/generate_qa_answers.py \
  --server http://127.0.0.1:8366 \
  --benchmark-dir "/mnt/d/CCBwork/2026/8月/benchmark_v1_0_7/standard/quick" \
  --companies C017 C018 C020 \
  --id-prefix benchmark-v107
```

### 评测结果

```bash
cd /home/zzx/py/Memind-Local-Dev

RUN=20260826-093326

python3 dev-tools/python/evaluate_qa_results.py \
  --llm-hit \
  benchmark-results/qa-answers/$RUN/results.json \
  --top-k 5
```

评测输出目录自动跟随输入目录名：输入 `qa-answers/<run>/`，输出到 `qa-evaluation/<run>/`。

## 5. 输出文件

- `results.json`：第一阶段结果
- `summary.json`：评测汇总
- `summary.csv`：逐题明细
- `report.md`：中文报告（如果启用）

## 6. 评分规则说明

### 检索命中（Hit@K / MRR）

- 默认字符串匹配：标准答案文本作为连续子串出现在检索结果中才算命中
- `--llm-hit`：字符串未命中时用 LLM 判定语义命中，推荐使用
  - 否定型问题（"无跨界经营"类）字面无法命中，必须用语义判定
  - 负样本题（问其他公司数据）本就不该命中，会拉低表面命中率，分析时注意区分

### 回答评分（LLM 裁判 0/1/2）

裁判 prompt 含「正确拒答」规则：

- 标准答案为"无法确定"类时，回答表达无法确定即判 **2 分**（正确拒答），不要求附解释原因
- 标准答案含具体事实而回答说无法确定 → 0 分

生成侧回答提示词要求：缺失信息时回答"无法确定"并用一句话说明缺失内容。

## 7. 提示词改动单点验证

改动裁判或回答提示词后，无需跑完整评测即可验证：

```bash
cd /home/zzx/py/Memind-Local-Dev

python3 dev-tools/python/verify_prompt_changes.py \
  --results benchmark-results/qa-answers/<run>/results.json
```

- 裁判验证：挑出所有"无法确定"类题目逐条打分，预期全部 2 分
- 回答验证：构造缺失/正常两种场景，检查新提示词的回答行为

## 8. 注意事项

- 先确认记忆写入已经完成，再跑评测。
- `--id-prefix` 要和写入时一致。
- 若要快速验证，可以先只跑一家公司。
- 终端命令避免使用尖括号占位符，用 export 变量代替。
