## 2. 记忆写入

### 2.1 单 session 写入（测试 / 补写通用）

```bash
env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/write_one_session.py \
  --server $SERVER \
  --company $COMPANY --session $SESSION \
  --id-prefix $PREFIX --source-client $PREFIX
```

成功的标志：

- `[commit] status=200 ... "status":"SUCCESS"` 且 `itemIds` 非空
- `[verify] SUCCESS - data persisted`

批量补写多个 session：

```bash
for s in S002 S021 V104P143cce9b1163; do
  echo "===== 补写 $s ====="
  env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/write_one_session.py \
    --company $COMPANY --session "$s" \
    --id-prefix $PREFIX --source-client $PREFIX
done
```

> session 名大小写随意，脚本会自动匹配数据文件中的规范名。

### 2.2 全量批量写入（按公司）

推荐使用**专用并行程序** `parallel_write_companies.py`：单终端内公司间并行，终端实时显示进度面板，公司内保持会话顺序。

运行环境（推荐 conda 环境 `memind-ui`）：

```bash
conda activate memind-ui
cd /home/zzx/py/Memind-Local-Dev

python3 dev-tools/python/parallel_write_companies.py \
  --server $SERVER \
  --benchmark-dir "/mnt/d/CCBwork/2026/8月/benchmark_v1_0_7/standard/quick" \
  --companies C011 C012 C013 C014 C015 \
  --id-prefix $PREFIX --source-client $PREFIX \
  --parallel 2
```

依赖：`pip install -r dev-tools/python/requirements.txt`（`requests`、`rich`；`textual` 仅 demo 用）。

并行模式的特点：

- `--parallel N`：同一终端内最多 N 家公司同时写入（建议 2~3，避免超过 LLM 额度）
- 终端下实时刷新进度面板（rich Live 原地刷新，不滚动刷屏）：头部汇总（完成公司数/已用时间/总成功/总失败）+ 每家公司一行（进度条、已完成/总数、成功/失败数、当前 session）+ 底部事件日志
- 输出重定向到日志文件（非终端）时，自动退化为普通日志行，无乱码
- 公司内 session 仍按顺序写入，保证同一会话的消息顺序不乱
- LLM API 额度耗尽时，任一线程检测到会通知所有公司线程联动提前停止，已成功部分保留
- 输出目录 `benchmark-results/memory-generation-parallel/`，seen 记录同其他方式共用，可安全重跑与查漏

如需严格顺序批量写入，也可仍用原脚本（公司间串行）：

```bash
python3 dev-tools/python/generate_benchmark_memories.py \
  --server $SERVER \
  --benchmark-dir "/mnt/d/CCBwork/2026/8月/benchmark_v1_0_7/standard/quick" \
  --companies C002 C003 C004 C005 C006 \
  --id-prefix $PREFIX --source-client $PREFIX
```

说明：

- 已成功写入的 session 自动跳过（依据 seen 目录 + 服务器已有 item 双重判断），可安全重跑
- 单 session 约 1~5 分钟，一家公司约 1 小时；并行可同时推进多家公司

## 3. 查遗漏与补写

### 3.1 查某公司失败的 session

```bash
cd /home/zzx/py/Memind-Local-Dev/benchmark-results/memory-generation-seen
grep -L success $COMPANY/*.json
```

有输出 = 失败的 session 清单；无输出 = 该公司全部成功。

一次查多家：

```bash
grep -L success C00[2-6]/*.json
```

### 3.2 查询服务器上某 session 实际写入的 items

```bash
curl -s -X POST $SERVER/open/v1/memory/items/query \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"$PREFIX-$COMPANY\",\"agentId\":\"$PREFIX-$COMPANY-agent\",\"sourceClients\":[\"$PREFIX-$COMPANY-$SESSION\"],\"limit\":10}" \
  | python3 -c "import json,sys; data=json.load(sys.stdin); items=data.get('data',{}).get('items',[]); print('items=',len(items)); [print('-', i.get('text','')) for i in items]"
```

### 3.3 不按 sourceClient 过滤直接查公司全部 items

```bash
curl -s -X POST $SERVER/open/v1/memory/items/query \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"$PREFIX-$COMPANY\",\"agentId\":\"$PREFIX-$COMPANY-agent\",\"limit\":100}" \
  | python3 -c "import json,sys; data=json.load(sys.stdin); items=data.get('data',{}).get('items',[]); print('items=',len(items)); [print('-', i.get('text','')[:120]) for i in items]"
```

### 3.4 公司级实际 items 查询

```bash
for company in C001 C002 C003 C004 C005; do
  echo "===== $company ====="
  curl -s -X POST $SERVER/open/v1/memory/items/query \
    -H "Content-Type: application/json" \
    -d "{\"userId\":\"$PREFIX-$company\",\"agentId\":\"$PREFIX-$company-agent\",\"limit\":10000}" \
    | python3 -c 'import json,sys; data=json.load(sys.stdin); result=data.get("data") or data.get("result") or data; items=result.get("items",[]) if isinstance(result,dict) else []; print(f"实际 items: {len(items)}"); print("✅ 服务器中存在记忆" if items else "❌ 服务器中没有记忆")'
done
```

该命令直接查询服务器实际数据，不依赖 seen 记录；`PREFIX` 必须与写入时一致。

### 3.5 用 verify_company.py 逐 session 验证前五家公司

```bash
env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/verify_company.py \
  --server "$SERVER" \
  --companies C001 C002 C003 C004 C005 \
  --id-prefix "$PREFIX"
```

判断方式：

- `✅ 有效`：该 session 至少有正常记忆条目
- `⚠ 部分问题`：服务器有条目，但文本质量规则认为部分文本过短；短文本不一定是错误
- `❌ 无效(假成功)`：查询不到该 session 的实际 items，需要补写

### 3.5 语义检索验证（模拟问答检索）

```bash
curl -s -X POST $SERVER/open/v1/memory/items/query \
  -H "Content-Type: application/json" \
  -d "{\"userId\":\"$PREFIX-$COMPANY\",\"agentId\":\"$PREFIX-$COMPANY-agent\",\"query\":\"拜访方式 更正 电话沟通 现场拜访\",\"limit\":10}" \
  | python3 -c "import json,sys; data=json.load(sys.stdin); [print('-', i.get('text','')[:120]) for i in data.get('data',{}).get('items',[])]"
```

## 4. 问答评测

### 4.1 生成回答（检索 + LLM 作答）

```bash
env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/generate_qa_answers.py \
  --server $SERVER \
  --benchmark-dir "/mnt/d/CCBwork/2026/8月/benchmark_v1_0_7/standard/quick" \
  --companies $COMPANY \
  --id-prefix $PREFIX
```

输出到 `benchmark-results/qa-answers/<新时间戳>/results.json`。

### 4.2 评测打分（推荐带语义命中）

```bash
NEW_RUN=$(ls -t benchmark-results/qa-answers | head -1)
echo "评测目录: $NEW_RUN"

env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/evaluate_qa_results.py \
  --llm-hit \
  benchmark-results/qa-answers/$NEW_RUN/results.json
```

输出自动跟随输入目录名：`qa-evaluation/<同样的时间戳>/`。

### 4.3 对已有 results.json 重跑评测（不重新生成回答）

```bash
RUN=20260826-161556

env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/evaluate_qa_results.py \
  --llm-hit \
  benchmark-results/qa-answers/$RUN/results.json
```

### 4.4 查看评测结果

```bash
cat benchmark-results/qa-evaluation/$RUN/summary.json     # 汇总指标
column -s, -t < benchmark-results/qa-evaluation/$RUN/summary.csv | head -25   # 逐题明细
cat benchmark-results/qa-evaluation/$RUN/report.md        # 中文报告
```

关键指标含义：

| 指标       | 含义                                                        |
| ---------- | ----------------------------------------------------------- |
| Hit@5      | 标准答案是否出现在 top-5 检索结果中（--llm-hit 为语义判定） |
| MRR        | 命中排名的倒数均值，越接近 1 排序越好                       |
| 平均分     | LLM 裁判 0/1/2 打分的均值，≥1.9 说明回答基本全对           |
| ≥1 分比例 | 至少部分正确的比例                                          |

评分规则要点：标准答案为"无法确定"类时，回答表达无法确定即判满分（正确拒答）；标准答案含具体事实而回答说无法确定则判 0 分。

## 5. 改动源码后的重新构建

改过 `memind-core` 或插件模块后，必须 install 并重启后端才生效：

```bash
mvn -pl memind-core,memind-plugins/memind-plugin-ai-spring-ai install \
  -DskipTests \
  -Dmaven.repo.local=/home/zzx/.m2/repository \
  -Duser.home=/home/zzx
```

然后按第 1 节重启后端。

跑单元测试（离线模式）：

```bash
mvn -o -pl memind-core test -Dmaven.repo.local=/home/zzx/.m2/repository -Duser.home=/home/zzx
```

格式修复（Spotless 报错时）：

```bash
mvn -o -pl memind-core spotless:apply -Duser.home=/home/zzx
```

提示词改动单点验证（不跑完整评测）：

```bash
env -i HOME="$HOME" PATH="$PATH" python3 dev-tools/python/verify_prompt_changes.py \
  --results benchmark-results/qa-answers/$RUN/results.json
```

## 6. 常见问题速查

| 问题                               | 处理                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| commit 返回 500 Server Error       | 多为 LLM 临时抖动，用 write_one_session.py 重试该 session 即可                   |
| commit 成功但 itemIds=[]           | LLM API 假成功（额度/推理模型问题），见`docs/memory-write-llm-issues-guide.md` |
| spotless check 导致构建失败        | `mvn spotless:apply` 后重跑                                                    |
| verify items found: 0 但日志有落库 | sourceClient 过滤不一致，用 3.3 节的无过滤查询确认                               |
| 测试期望旧文本失败                 | 提示词内容更新后同步修测试断言（08-26 已全部修复）                               |
