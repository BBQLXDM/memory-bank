# 知识图谱说明

> 这份文档说明 Memind 的知识图谱是怎么存的、怎么连的、怎么查的。
> 只保留关键结构和当前实现，不写实验结果。

## 1. 图谱是怎么存的

### 1) 不是 Neo4j，而是关系型表

当前运行态使用的是 **SQLite**，也支持 MySQL / PostgreSQL。图数据并不是存在专门的图数据库里，而是拆成多张表存。

### 2) 核心思想

- **实体**存一张表
- **实体提及**存一张表
- **item 之间的连接**存一张表
- **共现、别名、批记录**再用辅助表补充

这样既能保存关系，也能直接落在现有数据库里。

## 2. 主要表

| 表名 | 作用 |
|---|---|
| `memory_graph_entity` | 实体表，存节点 |
| `memory_item_entity_mention` | 实体提及表，存 item 和实体的对应关系 |
| `memory_item_link` | item 之间的边 |
| `memory_entity_cooccurrence` | 实体共现统计 |
| `memory_graph_entity_alias` | 实体别名 |
| `memory_item_graph_batch` | 图写入批次记录 |
| `memory_graph_alias_batch_receipt` | 别名批回执 |

## 3. 边是怎么来的

图里的连接主要有三类：

- **语义链接**：靠向量相似度连起来
- **时间链接**：靠时间先后和时间窗重叠连起来
- **因果链接**：靠因果提示连起来

## 4. 为什么用关系型数据库

- 现在图规模不大，关系型已经够用
- 统一存到 SQLite，启动和备份更方便
- 不用再额外部署 Neo4j 之类的独立服务

## 5. 什么时候会用到图

图不是单独给人查的，而是给检索用：

1. 先检索出初始记忆
2. 再沿着实体、时间、因果关系扩展
3. 最后把扩展出来的候选一起参与回答

## 6. 一句话总结

**图谱就是“实体表 + 提及表 + 链接表 + 辅助表”的组合，当前默认落在 SQLite 里，不是 Neo4j。**
